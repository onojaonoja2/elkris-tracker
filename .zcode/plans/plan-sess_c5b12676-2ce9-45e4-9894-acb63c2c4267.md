## PHASE 1 — Critical Security (C1–C4)

**`app/Filament/Pages/ManagerDashboard.php:125-129`**

### C2 + H3. Server-side role enforcement + UserResource guards
- **`CreateUser.php`** & **`EditUser.php`**: add `mutateFormDataBeforeCreate()` / `mutateFormDataBeforeSave()` that re-validate the submitted `role` is in `array_keys(UserForm::getRoleOptions())` for the current user; abort(403) otherwise. - **`ManagerDashboard.php:131-140`**: re-validate `$data['role']` is in `['open_market','retail_market']` before `User::create()`.
- Remove `role` from `User::$fillable` (set explicitly in handlers) — **optional hardening**, will confirm because it may affect existing code paths.

### C3. Harden SystemMaintenance SQL runner
**`app/Filament/Pages/SystemMaintenance.php`**
- Add a denylist check (after uppercasing) for: `INTO OUTFILE`, `INTO DUMPFILE`, `LOAD_FILE`, `LOAD DATA`, `SLEEP(`, `BENCHMARK(`. Reject if found.
- `clearTable()` / `dropTable()` / `truncateAllData()`: validate `$tableName` against the **live** `getTableList()` allowlist (currently only checks a small static denylist) before any destructive op. Reject anything not in the live list.

## PHASE 2 — High Security (H1, H2, H4)

### H1. Add `canAccess()` to 12 dashboard pages
For each file in `app/Filament/Pages/*Dashboard.php` (`ManagerDashboard`, `SalesOrdersDashboard`, `AccountantDashboard`, `GeneralAccountantDashboard`, `GeneralManagerDashboard`, `LeadDashboard`, `RepDashboard`, `SupervisorDashboard`, `WarehouseManagerDashboard`, `CsrDashboard`, `AgentDashboard`, `FieldAgentDashboard`):
```php
public static function canAccess(): bool
```

## PHASE 3 — Critical Performance (P1, P2, P3, P4)

### P1. Eliminate N+1 in portfolio widgets
**`RepPortfolioWidget.php`**, **`LeadPortfolioWidget.php`**, **`LeadPersonalPortfolioWidget.php`** — restructure the base `->query(...)` to precompute everything:
```php
Customer::query()
    ->where(/* role scope */)
    ->withCount(['orders as total_purchases' => fn ($q) => $q->where('status','delivered')->where('is_migrated_order', false)])
    ->withExists(['orders as has_orders' => fn ($q) => $q->where('is_migrated_order', false)])
    ->withMax(['callLogs as last_called_at' => fn ($q) => null], 'called_at') // for last_called column
```
Then read `$record->total_purchases`, `$record->has_orders`, `$record->last_called_at` directly instead of re-querying in `getStateUsing()`. Eliminates 100–200 queries/render → **3 queries total**.
- **`LeadCsrSubmissionsWidget.php:40-46`**: add `->with('agent')`.
- **`ManagerConversionWidget.php`** & **`ManagerPortfolioPerAgentWidget.php`**: replace per-row closures with `withCount(['reps','customers as converted_customers' => fn($q)=>...])` on the base query; compute `conversion_rate` in PHP from the cached counts.
- **`LeadCsrAssignmentWidget.php:66-93,161-174`**: preload reps once with `User::whereIn('id', $repIds)->pluck('name','id')` and look up in memory.

### P2. Stream exports chunk-by-chunk
**`LeadOrdersWidget.php:122-138`**, **`LeadPersonalPortfolioWidget.php:133-168`**, **`LeadPortfolioWidget.php:135-164`**, **`RepPortfolioWidget.php:124-153`**, **`OrderResource.php:200-203`**, **`ListStockTransfers.php:23-25`**:
Replace `->get()` + in-memory array with `chunkById(500, function ($chunk) use ($fh) { ... })` **inside** the `streamDownload` closure, writing CSV rows to `php://output` per chunk. Also fix the per-customer `orders()->count()` in the loop by using `withCount` on the base export query.

### P3. Add caching to aggregate widgets
Wrap the `GROUP BY state/region` queries in:
```php
Cache::remember("manager.sales.by_state.{$stateId}", now()->addMinutes(5), fn () => ...)
```
For: `ManagerCreditSalesWidget`, `ManagerSalesRecordsByStateWidget`, `ManagerTrialOrdersByStateWidget`, `SupervisorSalesByGeoWidget`. Keys scoped per-user where the data is role-scoped. Invalidate on `SalesRecord`/`TrialOrder` save via existing observers (add a `Cache::forget`).

### P4. Confirm queue readiness for listeners
- Audit the 10 `app/Listeners/Notify*` classes. Any doing >1 DB write or sending SMS should `implement ShouldQueue` with a `$queue` property and an `ShouldQueue` interface. Add a doc note for future exports-as-jobs (larger refactor — **flagging but not implementing** unless you confirm).

## PHASE 4 — High Performance (P5, P6, P7)

### P5. Composite database indexes
Create one migration `php artisan make:migration add_performance_indexes --table=customers` adding:
- `customers` → `['rep_acceptance_status']`, `['lead_id','rep_acceptance_status']`, `['rep_id','rep_acceptance_status']`
- `orders` → `['customer_id','status','is_migrated_order']`
- `sales_records` → `['agent_id','status']`, `['credit_status']`
Use `$table->index([...], 'name')`. Migration runs idempotently (Laravel skips existing indexes).
